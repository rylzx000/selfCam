## Context

本次是测试与检测增强，不改变小程序运行时逻辑。检测应保持克制：过期文案重点拦截当前三阶段主流程页面、开始页、拍照引导和用户主流程说明中的误导性旧引导；AI 专项文档、AI 状态枚举、AI 调试/日志说明中的自动拍照状态文案属于允许范围。OpenSpec / Comet 临时产物检测按要求覆盖 active change 与 archive change。

后续追加的破坏性压测覆盖清单只做测试地图和缺口管理，不替代既有流程矩阵、异常流清单或运行指引；首批新增用例优先选择可在现有 Jest harness 中表达的 P0/P1 风险，不新增页面能力、不调整业务逻辑。

## Approach

- 使用单个 Jest 文件集中承载静态检测，便于开发者按文件单独执行。
- 使用 Node.js 内置 `fs`、`path` 递归读取文件，不引入新依赖。
- 对流程矩阵只强制 `已覆盖`、`已补充`、`本轮补充` 且未标记 `需真机`、`抽测`、`暂未覆盖`、`不覆盖` 的用例 ID。
- 对无 `mode` 预览跳转采用精确白名单，覆盖字符串字面量、`PREVIEW_PAGE_URL` 和 `previewUrl` 变量用法；`previewUrl` 必须以最近有效赋值来自 `getPreviewPageUrl(...)` 为放行前提，报错时输出最近赋值行。
- 对过期文案扫描 `packageD/pages` 当前页面、`packageD/utils/ai-config.js` 与 `PRDS` 当前主文档，用克制正则覆盖旧自动拍照、证件叫法和车损数量变体；AI 专项章节、AI 状态枚举、AI 调试/日志说明放行，并对明确非用户可见采集项的“身份证”否定语境做白名单。
- 对素材检测只读 `packageD/assets`，不压缩、不删除、不改素材。
- 对 OpenSpec / Comet 临时产物只扫描 `openspec/changes` 下 active change 与 archive change，按临时文件名、临时扩展名、zip 临时包和编辑器备份文件识别，不禁止正常 `.comet` 元数据。
- 新增 `docs/destructive-stress-test-coverage.md`，按缓存恢复、路由乱序、删除重拍、多车隔离、容量边界、上传恢复、权限异常和质量门禁归纳已有覆盖。
- 首批自动化补强聚焦三处缺口：模块二少于 3 张车损软确认连续点击/取消/完成不重复推进；最终预览全局乱序删除后各补拍入口保持 `final`；上传恢复时 `uploading` 回落 `pending` 且 `success` 不重传。
- 对已被现有用例充分覆盖的模块一现场补充一次性弹层和 `complete_failed` 只重试 complete，不重复新增同义测试，只在覆盖清单中标为已覆盖并索引关联文件。

## Guardrails

- 错误信息必须包含文件路径和命中内容；流程矩阵包含缺失 ID，预览跳转包含行号、代码片段和建议，文案包含替换方向，素材包含大小和阈值，临时产物包含路径和命中原因。
- 过期文案不扫描历史方案、旧 AI 文档或全仓库 Markdown；当前主文档里的 AI 专项章节和 `packageD/utils/ai-config.js` 的 `STATUS_TEXT` 状态枚举不按主流程误导文案处理。
- 不修改业务代码、页面功能、页面样式或流程逻辑。
- 本轮按用户要求不运行 Jest、OpenSpec validate、语法检查或微信开发者工具自动化。
- 破坏性压测清单只记录和推荐执行方式，不把真机专项伪装成 Jest 已覆盖；涉及真实相机权限、真实文件写入、低端机横屏和真实 50 张图片滑动删除的场景继续标记为需真机。
