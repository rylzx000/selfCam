## Context

项目已经完成 OpenSpec 基线归档，并将六项能力同步到 `openspec/specs/`。审查发现正式规格缺少 Purpose 和部分已上线交互，案件级现场照片上传被文档描述为已实现但当前上传队列尚未组装；同时 Comet 的自动提交要求与项目 Git 安全规则冲突。

## Goals / Non-Goals

**Goals:**

- 让 OpenSpec、PRDS、接口文档和当前代码状态使用一致口径。
- 保留案件级照片上传的目标接口设计，同时明确当前前端实现边界。
- 让 Comet 自动路由和 Git 操作遵守项目已有安全规则。
- 给当前文档和历史材料建立可识别的权威层级。

**Non-Goals:**

- 不实现案件级现场照片上传队列。
- 不修改小程序页面、缓存、接口调用或测试代码。
- 不重写已归档 baseline change 和历史 CHANGELOG。
- 不自动 commit、push 或创建分支。

## Decisions

### 1. 正式规格描述稳定要求，状态说明描述实现进度

案件级上传的接口要求继续保留在 `backend-integration`，同时在正式 spec 和技术文档中明确当前 `upload-state.js` 尚未组装案件级照片。后续业务代码完成后再移除待实现说明。

### 2. 不修改已归档 baseline change

归档目录保留当时的 proposal、design、tasks 和来源映射。当前修订通过新的 change 和主规格完成，避免改写历史过程。

### 3. Comet 路由由任务性质决定

新能力、公共接口、schema、跨模块状态流或架构调整使用 full；明确范围的 bug 使用 hotfix；文档、配置和可收敛的中等改动使用 tweak。用户仍可明确覆盖默认路由。

### 4. Git 提交始终需要用户授权

Comet 可以完成任务、勾选 tasks 和执行验证，但不得自动 commit。需要 worktree 或归档提交时，先请求用户授权；未授权时保留工作区修改并报告状态。

### 5. 历史文档不伪装为当前事实

`PRDS/requirements.md` 更新为当前三阶段流程；带明确旧版本基线的测试文档保留历史内容，不批量改写。接口和技术文档中的当前事实错误直接修正。

## Risks / Trade-offs

- [案件级上传仍未实现] → 在正式规格和技术文档显式标记，后续用独立 change 实现并验证。
- [Comet 上游技能仍包含自动提交假设] → 修正项目内实际使用的规则和相关子技能，并通过全文搜索确认没有遗留强制提交指令。
- [历史文档较多] → 本轮只修正仍标记为当前事实或会直接误导开发的文件，其余通过版本基线和来源层级识别。
- [修改文件数较多] → 保持单一目标，不改业务代码，使用 OpenSpec strict validation 和文本一致性扫描验证。
