## Why

正常拍摄流程中用户点击“查看已拍”会进入临时预览，但当前补拍或新增照片后容易被统一带回预览页，导致模块一强顺序采集和模块二车损继续拍摄语义被打断。现在需要把“临时查看已拍”“正式预览补拍”“最终预览重拍”“新增车损”区分开，保证拍摄完成后的下一步符合动作语义。

## What Changes

- 新增轻量拍摄返回策略上下文，用于区分继续模块一、继续车损拍摄、返回预览三类拍摄完成后的流转。
- 新增临时预览来源上下文，明确标记拍摄页“查看已拍”形成的模块一 / 模块二临时预览，避免预览页加载或 safe resume 过早清理后误判为正式预览。
- 模块一临时预览空槽补拍后，按固定顺序扫描下一个未拍必拍项，全部完成后才进入模块一预览。
- 模块一正式预览空槽补拍、任意已有照片重拍、最终预览空槽补拍 / 新增 / 重拍，完成后仍返回对应预览。
- 模块二新增车损照片完成后继续停留当前车辆车损拍摄流程，重拍已有车损照片完成后返回当前预览上下文。
- 流程路由矩阵补充真实完整链路用例，覆盖相机页点击查看已拍、预览页生命周期、点击空槽 / `+` / 重拍、相机页确认照片后的完整流转。
- 保持删除车损后的数组重排和编号连续逻辑，不修改 UI 样式、上传接口或后端对接逻辑。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `preview-flow`: 明确临时预览、正式预览、最终预览下补拍/新增/重拍后的拍摄返回策略。

## Impact

- 影响文档：现有流程说明文档、流程路由测试矩阵。
- 影响测试：`__tests__/workflow-route-matrix.test.js`。
- 影响代码：`packageD/pages/camera/camera.js`、`packageD/pages/preview/preview.js`，必要时涉及状态选择工具。
- 不影响上传接口、后端初始化/完成接口、页面视觉样式、车损最多 10 张提示文案。
