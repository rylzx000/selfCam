## Context

当前拍摄流程里 `fromPreview` 同时承载了“从预览进入相机”和“拍完是否回预览”的含义。用户在正常拍摄页点击“查看已拍”进入模块预览时，这个预览只是临时查看入口；如果再点击空槽补拍，拍完后应继续原模块的自然采集流程，而不是一律回预览。已有照片重拍和正式预览补拍则仍需要回到当前预览，方便确认替换或补拍结果。

## Goals / Non-Goals

**Goals:**

- 用显式返回策略区分 `continueModuleOne`、`continueDamage`、`returnPreview`。
- 模块一临时预览空槽补拍后，按整车 45 度、每辆车车牌、每辆车 VIN 的顺序查找下一个未拍必拍项。
- 模块二区分新增车损和已有车损重拍，并在多车场景下锁定当前车辆。
- 拍摄完成后及时清理返回策略上下文，避免污染下一次拍摄。
- 通过路由矩阵测试覆盖本轮指定场景。

**Non-Goals:**

- 不修改页面视觉样式。
- 不修改上传接口、后端对接逻辑或缓存结构的持久化格式之外语义。
- 不处理车损最多 10 张提示优化。
- 不重构与本轮返回策略无关的流程代码。

## Decisions

- 引入显式 `captureReturnStrategy` 字段，而不是继续扩大 `fromPreview` 语义。这样可以保留现有预览来源判断，同时让拍摄完成后的路由意图可测试、可清理。
- 空槽点击时由预览页根据当前预览模式、临时预览标记和照片动作写入返回策略：临时模块一空槽使用 `continueModuleOne`，新增车损使用 `continueDamage`，正式补拍或重拍使用 `returnPreview`。
- 相机确认照片后优先消费并清理 `captureReturnStrategy`，再决定继续自然流程或返回预览，避免下一次拍照沿用旧策略。
- 模块一“下一个未拍必拍项”按全局案件现场主照片和车辆数组顺序扫描，不只依赖当前车辆索引。

## Risks / Trade-offs

- 返回策略字段若未清理可能造成后续流程误跳转 → 在确认照片后集中清理，并用测试覆盖不同来源的连续拍摄。
- 多车车损新增若只依赖全局当前车辆索引可能串车 → 新增车损入口保留目标车辆索引，相机确认后继续当前车辆车损拍摄。
- 现有测试可能依赖旧 `fromPreview` 行为 → 只调整与本轮返回策略直接相关的断言，保留原有预览返回语义。
