## Context

当前 `buildVehicleDocumentDisplayItems()` 已能在同一车辆同一证件类型已有照片时生成缺失 side 入口，但规则过宽：实物正页 + 副页已齐全时仍生成电子证件 `+`，只有电子证件时仍生成实物正页/副页 `+`。

预览页打开证件弹层时还会立即写入 `documentSelections`，导致用户只是误点入口或打开弹层后关闭，也可能把已完成的实物证件切成 `electronic` 选择，使完成状态从已完成变成待补充。

## Goals / Non-Goals

**Goals:**

- 电子证件和实物证件满足其一即可完成，不要求三张全部补齐。
- 已上传证件照片全部展示；首次未采集时展示整体入口，实物链路已开始但正副页尚未齐全时展示缺失实物侧入口。
- 只有实物正页或电子 + 实物正页时展示副页入口；只有实物副页或电子 + 实物副页时展示正页入口；只有电子证件、实物正副页齐全或三张齐全时不展示额外 `+`。
- 缺失的正页、副页入口带上 `vehicleIndex`、`docType`、`docSide` 和目标证件模式。
- 点击实物缺失入口默认打开实物证件面板，并展示正页/副页槽位。
- 打开弹层和切换 tab 本身不写入完成方式；只有实际上传照片成功后才更新 `documentSelections`。
- 模块三预览和最终预览都覆盖至少一组页面可操作性回归测试。

**Non-Goals:**

- 不修改上传接口、缓存 schema、后端字段或 complete 逻辑。
- 不恢复身份证采集。
- 不重构证件弹层视觉结构或来源选择菜单。
- 不大规模重写既有测试。

## Decisions

### 1. 展示项按完成规则生成

`buildVehicleDocumentDisplayItems()` 继续按驾驶证正页、驾驶证副页、电子驾驶证、行驶证正页、行驶证副页、电子行驶证的固定顺序展示已上传照片。提交完成态按 `电子证件存在 || 实物正页 + 副页同时存在` 计算；展示入口按实际 `E/F/B` 矩阵计算：完全没有照片时保留整体证件上传入口，只有电子证件时不生成实物入口，只有实物正页或电子 + 实物正页时生成副页入口，只有实物副页或电子 + 实物副页时生成正页入口，实物正副页齐全或三张齐全时不生成额外入口。

### 2. 缺失实物槽位显式携带目标模式

缺失正页/副页入口携带 `documentMode: 'physical'`。预览页点击入口时优先使用入口传入模式，整体证件入口只打开面板，不立即写入 `documentSelections`。

### 3. 完成方式只在上传成功后更新

弹层仍复用现有电子/实物切换、拍照、相册选择、查看、重新上传和删除逻辑。`onOpenDrivingLicensePanel()` 和 `onSwitchDrivingLicenseMode()` 只影响当前面板展示；`chooseDrivingLicenseImage()` 成功保存照片后，才根据 `docSide` 把当前采集方式更新为 `electronic` 或 `physical`。

## Risks / Trade-offs

- Jest 可以验证数据、绑定和点击上下文，仍建议在微信开发者工具或真机横屏下抽测补拍入口的可点击区域。
- 如果用户历史上确实上传了电子证件和实物正副页，预览区会展示三张照片，但不再提示继续补缺失项；若处于电子 + 实物单侧的过渡态，则仍提示补齐另一侧实物证件。
