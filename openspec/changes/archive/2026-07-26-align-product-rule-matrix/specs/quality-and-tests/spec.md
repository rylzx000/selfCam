## ADDED Requirements

### Requirement: 产品规则矩阵作为测试规则事实源

系统 MUST 维护一份产品规则矩阵文档，用于定义模块一、模块二、模块三、最终预览、断点续传和异常场景的测试规则事实源。测试矩阵、测试运行说明、Jest、页面可操作性测试、automator/e2e 和真机 smoke 的设计 SHOULD 以该矩阵为准；当旧测试或旧文档与产品规则矩阵冲突时，必须把冲突标记为规则漂移并在后续测试修正中处理。

#### Scenario: 测试说明引用产品规则矩阵
- **WHEN** 维护流程路由矩阵或测试运行说明
- **THEN** 文档 MUST 明确声明测试规则以 `docs/product-rule-matrix.md` 为准
- **AND** 流程路由矩阵不得替代产品规则矩阵成为规则事实源

#### Scenario: 当前旧规则漂移被显式标记
- **WHEN** 已知测试或说明仍包含车损 5 张上限、证件入口旧 actionSheet、模块三缺证件旧 toast 或过度依赖方法调用与 `setData` 的问题
- **THEN** 产品规则矩阵 MUST 把这些问题列为当前已知规则漂移点
- **AND** 测试运行说明 MUST 指向下一轮按矩阵修正 Jest/e2e 和页面可操作性测试

#### Scenario: 测试层级职责清晰
- **WHEN** 为任一主流程或异常场景设计测试
- **THEN** 产品规则矩阵 MUST 标记建议测试层级
- **AND** Jest MUST 优先覆盖规则、状态和路由
- **AND** 页面可操作性测试 MUST 覆盖页面入口是否存在、能否点击、点击后去向
- **AND** automator/e2e MUST 覆盖真实页面主链路和高风险恢复链路
- **AND** 手工或真机验证 MUST 覆盖相机硬件、权限、横屏适配、真实触摸区域和微信环境差异
