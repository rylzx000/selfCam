## Context

本次优化集中在预览页内部交互。现有规格已经要求模块三作为车辆证件采集入口、阶段切换必须经过统一确认弹层、相册保存确认只在最终提交前出现。现实现还保留了电子/实物证件原生菜单、模块三证件缺失 toast 和解释型交接弹层文案，需要按用户确认的弹窗治理口径收敛。

## Goals / Non-Goals

**Goals:**

- 减少证件上传链路中的原生菜单打断，证件模式选择统一放回自定义证件面板。
- 保持证件来源选择和已上传证件操作菜单不变。
- 删除模块三进入最终预览前的一闪而过证件缺失 toast。
- 让模块交接弹层只表达完成状态、下一步和待补充项。
- 同步弹窗清单文档，并补充测试覆盖。

**Non-Goals:**

- 不修改后端接口、ticket 初始化、上传队列或 complete 逻辑。
- 不修改拍照页、拍摄指引弹层和拍后确认态。
- 不修改上传/完成状态遮罩。
- 不清理无关组件或历史残留方法。
- 不大范围重构预览页布局。

## Decisions

### 1. 证件入口直接打开自定义面板

`onOpenDrivingLicensePanel` 不再调用电子/实物选择 `wx.showActionSheet`。它读取当前车辆当前证件的选择；若没有记录，则使用电子证件作为默认模式，然后直接调用现有面板打开逻辑。

### 2. 面板顶部切换电子/实物

在 `license-panel-header` 下方增加分段切换。切换仍复用现有 `onSwitchDrivingLicenseMode` 的缓存更新逻辑，但视觉位置从底部文本入口上移到面板顶部。实物模式继续展示正页/副页槽位；电子模式展示电子证件槽位。

### 3. 保留槽位级菜单

未上传槽位点击后继续弹 `拍照 / 从手机相册选择`；已上传槽位继续弹 `查看 / 重新上传 / 删除`。本次不改变这些原生菜单，避免扩大行为面。

### 4. 模块交接弹层复用现有遮罩样式

保留 `upload-mask` / `upload-modal` 的基础视觉和按钮路径，只把原说明文案替换为多行进度清单。证件到最终预览时根据当前车辆证件是否齐全，显示 `已完成：证件信息` 或 `待补充：证件信息`。

### 5. 文案更新保持最小范围

只更新用户明确指定的现场照片缺失文案和最终提交前证件风险文案；不调整上传遮罩、相册保存、三者车确认等其他弹窗文案。

## Risks / Trade-offs

- [视觉验证] 分段切换和进度清单需要在微信开发者工具或真机横屏下确认密度与点击区域。
- [历史 PRD 口径] 既有 PRD 中仍有旧行驶证面板描述；本轮用户范围限定不修改 `PRDS/`，后续提交前若需要可单独同步。
- [测试覆盖] Jest 能覆盖数据状态、文案和绑定，不能替代原生 action sheet 在真机上的视觉确认。
