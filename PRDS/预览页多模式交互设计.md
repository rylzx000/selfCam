# 预览页多模式交互设计

## 1. 文档说明

本文档用于定义三阶段查勘采集流程中“预览页”的模式划分、展示范围、点击规则、补拍返回规则和最终总预览规则。

本次文档重点解决以下问题：

- 同一套预览页承载多个采集阶段时，如何区分展示内容。
- 已拍照片、空槽位、缺失项分别应该如何交互。
- 从不同预览页发起补拍后，拍完应该返回哪个预览页。
- 模块预览页和最终总预览页的职责边界。
- 为后续 HTML 样板和小程序实现提供统一对照依据。

本文档只描述业务与交互规则，不展开具体代码实现、后端接口、上传策略和最终视觉样式细节。

## 2. 背景与问题

当前采集流程正在从原先的线性拍摄流程，调整为三个拍摄模块：

```text
模块一：现场环境及车辆信息
→ 模块二：车损照片
→ 模块三：证件信息
→ 最终总预览
→ 提交
```

由于车牌、VIN、车损、证件等照片都需要在预览页中查看、删除、重拍和补拍，如果预览页没有明确模式区分，容易出现以下问题：

- 模块一预览页点击已拍车牌或 VIN 时，被误判为老流程补拍入口。
- 模块一补拍完成后，错误跳转到最终总预览页。
- 模块二进入下一辆车时，错误回到车牌或 VIN 采集。
- 最终总预览照片过多，页面难以核对。
- 单元测试只覆盖局部逻辑，难以发现真实主流程跳转问题。

因此需要先明确预览页交互规则，再进行 HTML 样板和小程序实现。

## 3. 总体设计原则

### 3.1 一套预览页，多种模式

预览页建议继续复用同一套页面能力，通过明确的 `previewMode` 区分展示模式。

预览模式包括：

| 模式 | 名称 | 页面职责 |
|---|---|---|
| `moduleOne` | 现场环境及车辆信息预览 | 核对模块一拍摄内容 |
| `moduleTwo` | 车损照片预览 | 核对模块二拍摄内容 |
| `moduleThree` | 证件信息预览 | 核对模块三拍摄内容 |
| `final` | 最终总预览 | 提交前汇总核对全部内容 |

### 3.2 模块预览只展示本模块内容

每个模块预览页只展示本模块刚采集的内容。

原因：

- 用户刚完成一个模块，只需要核对当前模块产物。
- 避免模块一预览页出现车损、证件等后续未拍内容，造成误解。
- 避免模块二预览页混入车牌、VIN 等老流程补拍入口。
- 降低每个阶段页面复杂度，方便逐模块开发和验证。

最终总预览页才展示全部采集内容。

### 3.3 已拍照片和空槽位交互必须区分

预览页中所有图片槽位遵循统一规则：

| 槽位状态 | 点击行为 |
|---|---|
| 已拍照片 | 打开照片大图预览 |
| 未拍空槽位 | 直接进入对应拍摄页 |
| 缺失项提示 | 可点击时直接进入对应拍摄页 |

禁止将“已拍照片点击”直接处理成“进入相机补拍”。

### 3.4 补拍必须带返回上下文

从任何预览页发起补拍，都必须明确记录补拍来源。

建议至少具备以下上下文字段能力：

| 字段 | 说明 |
|---|---|
| `previewMode` | 当前预览页模式 |
| `returnPreviewMode` | 补拍完成后应返回的预览模式 |
| `captureTarget` | 本次补拍目标，如现场补充、车牌、VIN、车损、驾驶证、行驶证 |
| `vehicleIndex` | 车辆级照片对应车辆 |
| `photoIndex` | 多张同类照片对应序号 |

不能只靠 `currentStep = licensePlate / vinCode / damage` 判断返回页，因为这些拍摄步骤会被多个预览模式复用。

## 4. 页面名词定义

### 4.1 模块预览页

模块预览页是每个拍摄模块结束后的本模块核对页。

示例：

- 模块一预览页：只核对现场环境照片和车辆识别信息。
- 模块二预览页：只核对车损照片。
- 模块三预览页：只核对驾驶证、行驶证等证件照片。

### 4.2 照片大图预览

照片大图预览是点击已拍照片后打开的查看状态。

应支持：

- 查看当前照片大图。
- 删除照片。
- 重拍照片。
- 返回当前预览页。

照片大图预览不是新的流程页，而是预览页内的照片查看状态或弹层。

### 4.3 阶段完成弹层

阶段完成弹层用于模块完成后进入下一模块前的确认。

各模块弹层样式应保持统一，仅文案和下一步不同。

### 4.4 最终总预览页

最终总预览页用于提交前汇总核对全部照片。

最终总预览页承担：

- 展示全部模块采集内容。
- 展示缺失项和建议补拍信息。
- 进入最终提交。
- 在最终提交前询问是否保存照片到本地。

## 5. 模块一预览页：现场环境及车辆信息

### 5.1 展示范围

模块一预览页只展示模块一内容：

- 环境照片
  - 主现场照片。
  - 现场补充照片。
- 车辆识别信息
  - 每辆车车牌照片。
  - 每辆车 VIN 照片。

不展示：

- 车损照片。
- 驾驶证、行驶证。
- 最终提交信息。

说明：

- 拍摄引导页仍可明确要求“整车 45 度现场照片”。
- 预览页只做核对，展示短标签：`现场照片`、`补充照片`。
- 不使用 `2/3`、`3/3` 这类完成度数字，避免用户误解为必须拍满才能进入下一步。

### 5.2 推荐布局

```text
页面标题：现场环境及车辆信息

区块一：环境照片
  [现场照片] [补充照片] [补充照片]

区块二：车辆识别信息
  [标的车 - 京A12345]   [三者车 - 京B12345]
  [车牌号] [VIN码]      [车牌号] [VIN码]

底部操作：
  [补充现场照片] [进入车损拍摄]
```

### 5.3 点击规则

| 对象 | 已拍点击 | 空槽位点击 |
|---|---|---|
| 现场照片 | 打开大图预览 | 进入现场照片拍摄 |
| 补充照片 | 打开大图预览 | 进入现场补充照片拍摄 |
| 车牌号 | 打开大图预览 | 进入对应车辆车牌拍摄 |
| VIN码 | 打开大图预览 | 进入对应车辆 VIN 拍摄 |

### 5.4 补拍返回规则

从模块一预览页发起任何补拍，完成后必须返回模块一预览页。

包括：

- 补拍现场照片。
- 补拍现场补充照片。
- 补拍标的车车牌。
- 补拍标的车 VIN。
- 补拍三者车车牌。
- 补拍三者车 VIN。

返回目标为：

```text
/packageD/pages/preview/preview?mode=moduleOne
```

或等价的 `previewMode = moduleOne` 状态。

### 5.5 进入下一模块

点击“进入车损拍摄”后：

- 如现场照片缺失，给出明确提示，但不硬控。
- 展示阶段完成弹层。
- 用户确认后进入模块二车损拍摄。
- 模块二入口应直接进入车损照片拍摄，不应再进入车牌或 VIN 拍摄。

## 6. 模块二预览页：车损照片

### 6.1 展示范围

模块二预览页只展示模块二内容：

- 每辆车的车损照片。
- 每辆车最多 10 张车损照片。
- 未拍满时，在该车辆照片列表末尾展示 1 个 `+` 补拍入口。

不展示：

- 环境照片。
- 车牌、VIN 照片。
- 驾驶证、行驶证。
- 最终提交信息。

### 6.2 推荐布局

```text
页面标题：车损照片

标的车 · 京A12345
  [1] [2] [3] ... [10]

三者车 · 京B12345
  [1] [2] [3] [4] [5] [6] [+]

底部操作：
  [继续补拍车损] [进入证件采集]
```

### 6.3 多车和多照片布局原则

模块二是专门核对车损照片的页面，因此可以比最终总预览展示更多缩略图。

建议：

- 按车辆分组。
- 每组标题展示车辆身份和车牌文本，不展示 `10/10`、`20/20` 等完成度数字。
- 车损缩略图下方不展示 `标的车车损照片 1` 等长文案。
- 每张车损图只保留图片本身和图内短角标。
- 页面最多保留一处 `左右滑动查看更多照片` 提示。
- 未拍满时只追加 1 个 `+` 补拍入口，不用多个空槽补满 10 个位置。

### 6.4 点击规则

| 对象 | 点击行为 |
|---|---|
| 已拍车损照片 | 打开大图预览 |
| `+` 补拍入口 | 进入对应车辆车损拍摄 |

### 6.5 补拍返回规则

从模块二预览页发起车损补拍，完成后必须返回模块二预览页。

返回目标为：

```text
/packageD/pages/preview/preview?mode=moduleTwo
```

或等价的 `previewMode = moduleTwo` 状态。

### 6.6 进入下一模块

点击“进入证件采集”后：

- 如车损照片缺失，可给出提示，但不硬控。
- 展示阶段完成弹层。
- 用户确认后进入模块三证件采集。

模块二完成条件和缺失提示等级在模块二开发时细化。

## 7. 模块三预览页：证件信息

### 7.1 展示范围

模块三预览页只展示模块三内容：

- 每辆车的驾驶证。
- 每辆车的行驶证。

不展示：

- 环境照片。
- 车牌、VIN 照片。
- 车损照片。
- 最终提交信息。

### 7.2 车辆级证件展示

驾驶证和行驶证均按车辆展示。

每辆车一行，横向展示该车所有证件照片：

- 已采集证件照片直接展示。
- 未采集的证件类型展示 `+ 驾驶证` 或 `+ 行驶证`。
- 同一辆车内部不拆成“驾驶证一排 / 行驶证一排”。

用户点击某辆车下的 `+ 驾驶证` 或 `+ 行驶证` 后，再选择采集实物证件或电子证件。

### 7.3 驾驶证展示

驾驶证属于车辆级证件资料，按车辆分别采集和展示。

预览页展示标签：

- 实物驾驶证：`驾驶证-正页`、`驾驶证-副页`。
- 电子驾驶证：`驾驶证`。

原则：

- 用户上传了哪种就展示哪种。
- 一般情况下不会同时上传实物和电子，但页面应兼容。
- 选择采集方式的弹层中可以使用 `实物驾驶证`、`电子驾驶证` 文案。

### 7.4 行驶证展示

行驶证按车辆展示。

预览页展示标签：

- 实物行驶证：`行驶证-正页`、`行驶证-副页`。
- 电子行驶证：`行驶证`。

行驶证采集逻辑沿用当前系统已有行驶证拍摄逻辑，展示层使用上述短标签。

### 7.5 推荐布局

```text
页面标题：证件信息

标的车 - 京A12345
  [驾驶证] [行驶证-正页] [行驶证-副页]

三者车 - 京B12345
  [驾驶证-正页] [驾驶证-副页] [行驶证] [+ 行驶证]

底部操作：
  [继续补拍证件] [进入最终预览]
```

点击某个 `+ 驾驶证` 或 `+ 行驶证` 后，打开证件采集方式选择面板：

```text
补传标的车驾驶证
  [实物驾驶证] [电子驾驶证]
```

```text
补传标的车行驶证
  [实物行驶证] [电子行驶证]
```

### 7.6 点击规则

| 对象 | 点击行为 |
|---|---|
| 已拍证件照片 | 打开大图预览 |
| `+ 驾驶证` | 打开驾驶证采集方式选择面板 |
| `+ 行驶证` | 打开行驶证采集方式选择面板 |
| 实物驾驶证 | 进入对应车辆驾驶证正页 / 副页采集 |
| 电子驾驶证 | 进入对应车辆电子驾驶证采集 |
| 实物行驶证 | 进入对应车辆行驶证正页 / 副页采集 |
| 电子行驶证 | 进入对应车辆电子行驶证采集 |

### 7.7 补拍返回规则

从模块三预览页发起证件补拍，完成后必须返回模块三预览页。

返回目标为：

```text
/packageD/pages/preview/preview?mode=moduleThree
```

或等价的 `previewMode = moduleThree` 状态。

### 7.8 进入最终总预览

点击“进入最终预览”后：

- 如驾驶证或行驶证缺失，可给出提示，但不硬控。
- 展示阶段完成弹层。
- 用户确认后进入最终总预览。

证件缺失提示等级后续统一设计。

## 8. 最终总预览页

### 8.1 展示范围

最终总预览页展示全部采集内容：

- 现场环境及车辆信息。
- 车损照片。
- 证件信息。
- 缺失项和建议补拍提示。

### 8.2 推荐分组

最终总预览按前三个模块顺序叠加展示：

```text
页面标题：提交前总预览

一、现场环境及车辆信息
二、车损照片
三、证件信息

底部操作：
  [返回补拍/修改] [确认提交]
```

### 8.3 展示原则

最终总预览不是新的采集页，也不是完整照片墙，而是提交前核对清单。

采用原则：

- 模块一内容按模块一预览页结构展示。
- 模块二车损照片按车辆分组展示，默认只露出部分缩略图。
- 模块三证件信息按模块三预览页结构展示。
- 不展示 `现场 3/3`、`车损 20/20`、`证件 4/4类` 等完成度数字。
- 如有建议补拍项，只提示“有建议补拍项，可继续提交”，不硬控提交。

尤其是车损照片：

- 多车都拍满时，照片数量较多。
- 最终总预览不默认全部展开。
- 每辆车默认展示前几张缩略图。
- 提供 `查看全部10张` 入口，进入该车辆照片完整查看。
- 未拍满时，在默认区或全部查看弹层中只展示 1 个 `+` 补拍入口。

### 8.4 推荐布局

```text
请核对采集内容后提交

一、现场环境及车辆信息
  现场环境照片
    [现场照片] [补充照片] [补充照片]
  车辆识别信息
    标的车 - 京A12345：[车牌号] [VIN码]
    三者车 - 京B12345：[车牌号] [VIN码]

二、车损照片
  标的车 · 京A12345
    [1] [2] [3] [4] [查看全部10张]
  三者车 · 京B12345
    [1] [2] [3] [+] [查看全部10张]

三、证件信息
  标的车 - 京A12345
    [驾驶证] [行驶证-正页] [行驶证-副页]
  三者车 - 京B12345
    [驾驶证-正页] [驾驶证-副页] [行驶证] [+ 行驶证]
```

### 8.5 点击规则

| 对象 | 点击行为 |
|---|---|
| 已拍照片 | 打开大图预览 |
| 空槽位 / 缺失项 | 直接进入对应拍摄页 |
| 查看全部 | 展示该分组完整照片 |
| 提交 | 进入最终提交前确认 |

### 8.6 最终提交前本地保存提示

是否保存照片到本地，只在最终提交前询问一次。

各模块预览页不单独询问是否保存本地。

## 9. 补拍返回规则汇总

| 来源预览页 | 补拍内容 | 拍完返回 |
|---|---|---|
| `moduleOne` | 现场 45 度照片 | `moduleOne` |
| `moduleOne` | 现场补充照片 | `moduleOne` |
| `moduleOne` | 车牌 | `moduleOne` |
| `moduleOne` | VIN | `moduleOne` |
| `moduleTwo` | 车损照片 | `moduleTwo` |
| `moduleThree` | 驾驶证 | `moduleThree` |
| `moduleThree` | 行驶证 | `moduleThree` |
| `final` | 任意缺失项或照片 | `final` |

实现时必须保证：

- 发起补拍时记录来源预览模式。
- 拍摄页完成后读取来源模式。
- 返回来源预览页。
- 不因 `currentStep` 与老流程复用而丢失来源。

## 10. 阶段完成弹层

阶段完成弹层用于模块之间切换。

### 10.1 通用结构

```text
标题：{模块名称}已保存
说明：本环节照片将后台上传，可继续拍摄{下一模块名称}
下一步：{下一模块名称}

[返回预览] [进入下一步]
```

### 10.2 模块一弹层


## 11. 缺失提示原则

整体原则：

- 不硬控提交。
- 缺失时必须明确提示。
- 用户确认后仍可继续。

提示分层后续统一设计。

当前先按以下规则预留：

| 场景 | 处理 |
---|---|
| 模块一缺少整车 45 度现场照片 | 进入模块二前提示 |
| 模块二缺少车损照片 | 进入模块三前提示 |
| 模块三缺少驾驶证或行驶证 | 进入最终总预览前提示 |
| 最终总预览存在缺失项 | 提交前统一提示 |

## 12. HTML 样板要求

后续 HTML 样板应覆盖以下页面状态：

- `moduleOne`：现场环境及车辆信息预览。
- `moduleTwo`：车损照片预览。
- `moduleThree`：证件信息预览。
- `final`：最终总预览。
- 照片大图预览状态。
- 阶段完成弹层状态。
- 最终总预览“查看全部”状态。

HTML 样板重点验证：

- 各模式展示范围是否清晰。
- 照片多时是否方便查看。
- 已拍照片和空槽位是否容易区分。
- 阶段完成弹层是否统一。
- 手机横屏微信小程序场景下布局是否可用。

## 13. 小程序实现要求

后续实现时建议遵循：

- 继续复用一套预览页，但必须显式区分 `previewMode`。
- 不同 `previewMode` 的展示数据、点击行为和底部按钮应拆清楚。
- 补拍发起时必须写入 `returnPreviewMode`。
- 拍摄完成后按 `returnPreviewMode` 返回对应预览页。
- 已拍照片点击必须进入照片大图预览。
- 空槽位点击才进入对应拍摄页。
- 最终总预览中的补拍完成后应返回 `final`。
- 测试必须覆盖每个模式的展示、点击和返回。

## 14. 验收标准

### 14.1 模块一预览

- 只展示环境照片和车辆信息。
- 现场照片展示短标签：`现场照片`、`补充照片`。
- 车辆识别信息按车辆分组横向展示，每车内部展示 `车牌号`、`VIN码`。
- 已拍现场照片点击打开大图。
- 已拍车牌、VIN 点击打开大图。
- 空现场照片槽位点击进入现场照片拍摄。
- 空车牌、VIN 槽位点击进入对应车辆拍摄。
- 任意模块一补拍完成后返回模块一预览。
- 点击进入车损拍摄后进入模块二，不回到车牌或 VIN。

### 14.2 模块二预览

- 只展示车损照片。
- 按车辆分组展示。
- 不展示车损完成度数字和缩略图下方长文案。
- 未拍满时只在车辆照片列表末尾展示 1 个 `+` 补拍入口。
- 已拍车损点击打开大图。
- 车损补拍完成后返回模块二预览。
- 进入下一辆车车损时，不回到车牌或 VIN。

### 14.3 模块三预览

- 只展示驾驶证和行驶证。
- 按车辆分组展示，同一辆车的所有证件照片横向展示在一行。
- 电子驾驶证展示为 `驾驶证`。
- 电子行驶证展示为 `行驶证`。
- 实物证件展示为 `驾驶证-正页`、`驾驶证-副页`、`行驶证-正页`、`行驶证-副页`。
- 证件补拍完成后返回模块三预览。

### 14.4 最终总预览

- 按前三个模块顺序叠加展示现场环境及车辆信息、车损照片、证件信息。
- 车损照片多时具备摘要或查看全部能力。
- 车损缺失时只展示 1 个 `+` 补拍入口，不用多个空槽补满上限。
- 不展示完成度数字。
- 缺失项有明确提示。
- 缺失项补拍完成后返回最终总预览。
- 最终提交前才询问是否保存本地。
