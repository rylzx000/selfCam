# 模块一：现场环境及车辆信息设计

## 1. 文档说明

本文档用于描述“模块一：现场环境及车辆信息”的业务与交互设计。

模块一是本次三阶段采集流程中的第一个拍照模块，主要负责在车损照片拍摄前完成事故现场环境和车辆识别信息采集。

本文档重点说明：

- 模块目标
- 业务范围
- 用户流程
- 页面交互
- 预览确认
- 缺项提示
- 后端配置要求
- 验收标准

本文档不展开车损照片、证件照、完整上传策略和最终提交闭环，仅说明模块一进入下一模块时的保存与后台上传提示口径。

## 2. 模块定位

模块名称：现场环境及车辆信息

当前补充口径：

- 现场照片首次进入时自动展示 45 度拍摄指引弹窗。
- 拍摄页左侧底部提供 `45度示意` 入口，可再次打开同一指引弹窗。
- 指引弹窗标题为 `拍摄指引：整车照，45度角拍一张，包含现场环境`。
- 指引弹窗展示 45 度整车现场示例图，首次进入按钮为 `知道了，开始拍摄`，手动打开按钮为 `关闭`。
- 指引弹窗只遮挡操作并暂停 AI，不销毁相机组件。

模块一负责采集：

- 整车 45 度现场照片
- 标的车车牌号
- 标的车 VIN 码
- 三者车车牌号
- 三者车 VIN 码
- 其他现场环境补充照片

其中，整车 45 度现场照片和其他现场环境补充照片属于案件级现场资料。

车牌号和 VIN 码属于车辆级识别资料。

## 3. 设计目标

模块一的设计目标如下：

- 在进入车损拍摄前，先完成现场环境和车辆识别信息采集。
- 保持当前拍摄流程的线性体验，减少用户选择成本。
- 最大程度复用现有车牌号、VIN 码采集能力。
- 先强引导拍摄 1 张整车 45 度现场照片。
- 在本环节预览页提供其他现场环境照片补充入口。
- 缺少现场照片或车辆信息时不硬控，但需要明确提示。
- 为后端下发整案级和车辆级拍摄项预留配置能力。

## 4. 当前流程接入点

当前主拍摄流程大致为：

```text
车牌号
→ VIN 码
→ 车损照片
→ 预览页
```

模块一改造后，需要在现有车牌号采集前插入整车 45 度现场照片采集，并在车牌号、VIN 码完成后增加本环节预览页。

调整后的模块一流程为：

```text
现场照片
→ 标的车车牌号
→ 标的车 VIN 码
→ 三者车车牌号（如有）
→ 三者车 VIN 码（如有）
→ 本环节预览页
→ 如需补充其他现场环境照片，返回补拍后回到本环节预览页
→ 点击进入车损拍摄
→ 展示过渡弹层，提示本环节已保存并将后台上传
→ 进入模块二第一辆车车损照片拍摄
```

## 5. 交互设计原则

### 5.1 主链路线性推进

模块一继续采用线性拍摄方式。

用户不需要先进入任务清单自由选择拍摄项，而是按系统引导一步一步完成：

```text
先拍现场
再拍车牌
再拍 VIN
最后进入环节预览
```

这样可以保持当前产品的操作习惯，降低用户理解成本。

### 5.2 现场补充照片后置

模块开始时只强引导 1 张整车 45 度现场照片。

其他现场环境照片不放在主链路前面连续强拍，而是在本环节预览页中询问用户是否需要补充。

这样做的好处：

- 不打断主链路。
- 不让用户一开始感觉要拍很多环境照片。
- 保留业务需要的现场补充能力。
- 让用户在看完本环节采集结果后再决定是否补充。

### 5.3 复用现有车牌和 VIN 能力

标的车、三者车的车牌号和 VIN 码采集应尽量复用现有能力。

本模块不重新设计车牌识别、VIN 拍摄、确认态、重拍、缓存和识别逻辑。

模块一主要调整流程位置和环节收口方式。

### 5.4 不使用“提交”描述环节完成

本环节完成按钮不建议使用“提交”。

推荐使用：

- 完成本环节
- 进入车损拍摄

原因是“提交”容易让用户误以为已经完成整个案件采集，与最终提交动作混淆。

### 5.5 不设置模块一完成页

模块一结束时不设置独立“完成页”。

原因：

- 模块一不是整个采集流程完成，只是进入下一拍摄模块。
- 模块一的资料汇总职责由模块一预览页承担。
- 独立完成页容易与最终完成页混淆。

用户在模块一预览页点击“进入车损拍摄”后，应在当前预览页上展示轻量过渡弹层；确认后直接进入模块二第一辆车车损照片拍摄。

过渡弹层只表达：

- 现场环境及车辆信息已保存。
- 本环节照片将后台上传。
- 用户可以继续进入车损照片拍摄。

过渡弹层不展示照片汇总、车牌/VIN 明细和上传进度条。

## 6. 详细用户流程

### 6.1 进入模块一

用户从开始页进入拍摄流程后，首先进入模块一。

页面应明确告诉用户当前环节是：

```text
现场环境及车辆信息
```

建议展示阶段信息：

```text
第 1 步 / 共 3 步
现场环境及车辆信息
```

### 6.2 拍摄整车 45 度现场照片

模块一第一步为拍摄整车 45 度现场照片。

页面引导重点：

- 请拍摄车辆整体 45 度角照片。
- 尽量拍到整车、车牌、受损方向和现场环境。
- 该照片用于记录事故现场和车辆整体状态。

建议按钮文案：

```text
拍摄整车45度照片
```

拍摄后进入确认态。

确认态按钮：

- 确认使用
- 重新拍摄

确认使用后进入标的车车牌号采集。

### 6.3 标的车车牌号采集

整车 45 度现场照片完成后，进入标的车车牌号采集。

该步骤复用当前车牌号采集能力。

用户完成车牌号照片拍摄并确认后，进入标的车 VIN 码采集。

### 6.4 标的车 VIN 码采集

标的车车牌号完成后，进入标的车 VIN 码采集。

该步骤复用当前 VIN 码采集能力。

用户完成 VIN 码照片拍摄并确认后，判断是否存在三者车。

### 6.5 三者车车牌号与 VIN 码采集

如果后端下发三者车，则按车辆顺序继续线性采集。

三者车流程：

```text
三者车车牌号
→ 三者车 VIN 码
```

如果存在多辆三者车，则按后端下发顺序逐辆采集：

```text
三者车 1 车牌号
→ 三者车 1 VIN 码
→ 三者车 2 车牌号
→ 三者车 2 VIN 码
```

本轮主要面向单车事故，多车事故完整体验后续单独设计。

当前模块只要求在已有三者车数据时能够沿用线性采集，不新增复杂多车管理能力。

### 6.6 进入本环节预览页

所有车辆的车牌号和 VIN 码采集完成后，进入模块一预览页。

模块一预览页用于确认：

- 整车 45 度现场照片是否已采集
- 其他现场补充照片数量
- 标的车车牌号是否已采集
- 标的车 VIN 码是否已采集
- 三者车车牌号是否已采集
- 三者车 VIN 码是否已采集

### 6.7 询问是否补充其他现场环境照片

模块一预览页中展示现场补充入口。

建议文案：

```text
是否还有其他现场环境照片需要补充？
可补充道路环境、碰撞位置、周边参照物等照片。
```

建议按钮：

- 补充现场照片
- 进入车损拍摄

其他现场环境照片建议最多 2 张。

用户点击“补充现场照片”后，进入现场补充照片拍摄。

从模块一预览页进入补拍或重拍时，拍照页需要提供明确的“返回预览”入口。用户不想继续拍摄时，可以直接返回模块一预览页，不改变已有照片状态。

用户拍完补充现场照片并确认后，也应返回模块一预览页。

用户点击“进入车损拍摄”后，不进入独立完成页，而是在当前预览页上展示过渡弹层。

### 6.8 进入车损拍摄过渡弹层

过渡弹层用于承接模块一到模块二的跳转。

触发时机：

```text
模块一预览页
→ 点击进入车损拍摄
→ 如整车 45 度现场照片缺失，先展示缺失提示
→ 用户确认继续后，展示过渡弹层
→ 进入模块二第一辆车车损照片拍摄
```

弹层建议复用现有预览页上传/处理中弹层的视觉风格，但不展示进度条。

过渡弹层不触发“是否保存到手机相册”询问。照片是否保存到手机相册仍只在最终提交前统一询问。

弹层内容：

```text
现场环境及车辆信息已保存
本环节照片将后台上传，可继续拍摄车损照片
下一步：车损照片拍摄

[返回预览] [进入车损拍摄]
```

交互规则：

- 点击“返回预览”：关闭弹层，停留在模块一预览页。
- 点击“进入车损拍摄”：进入模块二第一辆车车损照片拍摄。
- 后台上传失败不应阻塞用户进入模块二，失败提示和重试机制以后续上传设计为准。
- 不在模块一结束时询问是否保存到手机相册；相册保存询问只出现在最终提交前。

## 7. 模块一预览页设计

### 7.1 页面定位

模块一预览页不是最终提交预览页。

它只负责收口“现场环境及车辆信息”环节。

模块一预览页是本模块唯一的资料汇总确认页。后续过渡弹层不再重复展示照片、车牌号或 VIN 明细。

页面目标：

- 帮用户确认本环节已经采集的资料。
- 暴露缺失项。
- 提供返回补拍入口。
- 询问是否补充其他现场环境照片。
- 触发进入车损拍摄的过渡弹层。

### 7.2 建议展示结构

```text
现场环境及车辆信息

环境照片
[现场照片] [补充照片] [补充照片]

车辆识别信息
[标的车 - 京A12345]   [三者车 - 京B12345]
[车牌号] [VIN码]      [车牌号] [VIN码]

[补充现场照片] [进入车损拍摄]
```

展示原则：

- 拍摄引导页仍可使用“整车 45 度现场照片”说明拍摄要求。
- 预览页只做核对，使用短标签 `现场照片`、`补充照片`。
- 不展示 `0 / 2`、`2 / 3` 等完成度数字，避免用户误解为必须拍满才能继续。
- 车辆识别信息按车辆分组横向展示，每辆车内部只展示 `车牌号`、`VIN码`。

### 7.3 返回补拍

预览页中每个缺失项或已拍项都应支持返回补拍。

建议交互：

- 点击未拍槽位：进入对应拍照页补拍。
- 点击已拍槽位：进入全屏照片预览。
- 全屏照片预览底部提供“重拍”和“删除”。
- 点击“重拍”：进入对应拍照页，拍完后返回模块一预览页。
- 点击“删除”：二次确认后删除照片，并返回模块一预览页。
- 从预览页进入补拍或重拍时，拍照页提供“返回预览”入口。

### 7.4 缺项提示

如果现场照片未采集，预览页应明显提示。

示例文案：

```text
现场照片未采集，建议补拍，便于记录事故现场和车辆整体状态。
```

按钮：

- 返回补拍
- 仍然进入车损拍摄

如果车牌号或 VIN 码未采集，也应提示，但不硬控。

### 7.5 进入下一模块弹层

模块一预览页点击“进入车损拍摄”后，应展示覆盖在预览页上的过渡弹层，而不是进入独立完成页。

弹层定位：

- 保存提示。
- 后台上传提示。
- 下一模块跳转确认。

弹层样式应与真实小程序预览页的上传/处理中弹层保持一致，语义上接近“已保存 / 处理中 / 进入下一步”，不使用普通确认弹层样式。

弹层不展示：

- 照片缩略图。
- 车辆明细。
- 车牌号 / VIN 汇总。
- 上传进度条。
- “采集完成”或“提交成功”等最终态文案。
- “是否保存到手机相册”等最终提交前才出现的确认内容。

## 8. 现场照片规则

### 8.1 整车 45 度现场照片

整车 45 度现场照片为模块一的重点引导项。

建议数量：

- 1 张

业务要求：

- 拍到车辆整体。
- 尽量拍到车牌。
- 尽量拍到受损方向。
- 尽量拍到事故现场背景。

### 8.2 其他现场环境补充照片

其他现场环境补充照片作为补充项。

建议数量：

- 最多 2 张

可拍内容：

- 道路环境
- 碰撞位置
- 周边参照物
- 事故现场其他辅助信息

补充照片不在主链路中强制拍摄，而是在模块一预览页询问用户是否补充。

### 8.3 现场照片与车损照片区分

现场照片不计入车损照片数量。

现场照片不进入车损照片列表。

现场照片应作为案件级资料独立展示和上传。

## 9. 后端配置要求

后端会配合下发整案级和车辆级拍摄项。

模块一需要支持两类拍摄项：

### 9.1 整案级拍摄项

整案级拍摄项用于现场环境照片。

建议包括：

- 整车 45 度现场照片
- 其他现场环境补充照片

建议后端支持字段：

- 拍摄项 ID
- 照片类型
- 展示名称
- 最大张数
- 是否建议采集
- 是否允许跳过
- 示例图
- 提示文案
- 已采集数量

### 9.2 车辆级拍摄项

车辆级拍摄项用于车辆识别信息。

包括：

- 车牌号
- VIN 码

车辆级拍摄项继续按车辆下发。

前端按后端下发车辆顺序进行线性采集。

## 10. 数据与缓存设计建议

### 10.1 案件级现场照片

现场照片建议使用案件级缓存结构，不挂到某辆车的车损照片中。

建议结构示意：

```js
scenePhotos: [
  {
    sceneType: 'WHOLE_VEHICLE_45',
    status: 'completed',
    compressedPath: '',
    uploadItemId: '',
    photoType: '',
    sortNo: 1,
    captureMode: 'manual'
  },
  {
    sceneType: 'SCENE_SUPPLEMENT',
    status: 'completed',
    compressedPath: '',
    uploadItemId: '',
    photoType: '',
    sortNo: 2,
    captureMode: 'manual'
  }
]
```

字段命名以后续技术实现为准。

### 10.2 车辆识别照片

车牌号和 VIN 码继续沿用现有车辆级缓存结构。

不建议在模块一中重写车牌号和 VIN 码的数据结构。

### 10.3 恢复规则

用户退出后重新进入时，应能恢复模块一采集进度。

建议恢复优先级：

1. 如果整车 45 度照片未完成，回到整车 45 度拍摄。
2. 如果整车 45 度已完成但车牌号未完成，回到车牌号拍摄。
3. 如果车牌号已完成但 VIN 码未完成，回到 VIN 码拍摄。
4. 如果模块一主链路完成，回到模块一预览页或进入下一未完成模块。

具体恢复逻辑以后续技术实现和现有缓存恢复机制为准。

## 11. 不做范围

模块一不处理以下内容：

- 车损照片数量扩展
- 车损远 / 中 / 近模板
- 驾驶证采集
- 行驶证采集
- 最终提交弹窗
- 完整上传策略
- 线下补件闭环
- 多车事故完整体验重构
- 现场照片 AI 识别
- 自动判断现场照片是否合格

## 12. 验收标准

### 12.1 主流程验收

- 用户进入拍摄流程后，先进入整车 45 度现场照片采集。
- 整车 45 度现场照片确认后，进入标的车车牌号采集。
- 标的车车牌号确认后，进入标的车 VIN 码采集。
- 标的车 VIN 码确认后，如无三者车，进入模块一预览页。
- 如有三者车，按后端车辆顺序采集三者车车牌号和 VIN 码。
- 所有车辆识别信息采集完成后，进入模块一预览页。
- 用户在模块一预览页可以选择补充现场照片。
- 用户在模块一预览页可以选择不补充并进入模块二第一辆车车损拍摄。

### 12.2 现场照片验收

- 支持拍摄 1 张整车 45 度现场照片。
- 支持最多 2 张其他现场环境补充照片。
- 现场照片不计入车损照片数量。
- 现场照片在模块一预览页独立展示。
- 现场照片缺失时有明确提示。
- 现场照片缺失时仍允许进入车损拍摄。

### 12.3 车辆信息验收

- 标的车车牌号采集能力保持可用。
- 标的车 VIN 码采集能力保持可用。
- 如后端下发三者车，三者车车牌号和 VIN 码采集能力保持可用。
- 车牌号和 VIN 码可从模块一预览页返回补拍。

### 12.4 兼容验收

- 现有车牌号识别、确认使用、重新拍摄逻辑不被破坏。
- 现有 VIN 码拍摄、确认使用、重新拍摄逻辑不被破坏。
- 现有进入车损照片拍摄的逻辑不被破坏。
- 模块一完成后能正常进入模块二第一辆车车损照片拍摄，不回到车牌号或 VIN 拍摄，也不跳到最终总预览页。
