# UI 设计文档

> 项目名称：车辆损失辅助拍照工具
> 代码基线：v1.3.6（`package.json`）
> 文档状态：已按当前实现对齐
> 最后更新：2026-05-04

---

## 一、UI/UX 基线

本次文档对齐前，先按 `ui-ux-pro-max` 对当前实现做了复核。保留并写入文档的关键建议如下：

- 常驻区域只放稳定信息，动态状态贴近取景区显示
- `camera + cover-view` 覆盖层内避免复杂连续动画，优先选择轻量、稳定的提示方式
- 手动拍照按钮始终保留，不能让 AI 抢走用户控制权
- 引导元素必须服务于取景框，不能比目标框更抢眼

---

## 二、视觉风格

- 主色：绿色系，延续拍照工具的安全、确认感
- 页面背景：开始页、拍照页、预览页统一使用浅灰绿色背景 `#f7faf8`，页面底色为 `#eef4ef`，右上角保留极淡绿色圆形装饰层
- 辅助色：白色、灰色、深色半透明蒙层
- AI 状态高亮：
  - 锁定/成功态偏亮绿或蓝绿
  - 覆盖层提示使用白字 + 半透明深底
- 页面风格偏工具化、低装饰，不追求重动画

## 三、页面结构

### 1. 开始页

#### 布局

- 左上角：品牌 logo `/assets/logo.png`
- 中部：标题 `车辆损失照片采集工具` 与副标题 `请按照提示完成车辆信息、车损照片及单证资料采集`
- 中部下方：`拍摄须知` 卡片，包含 3 条采集说明
- 底部：`开始采集` 按钮与权限提示
- 隐藏交互：非正式版连续点击左上角品牌 logo 7 次后弹出环境选择；正式版不响应该入口

#### 拍摄须知文案

- `拍摄前，请提前准备好所有事故车辆的行驶证（支持12123电子版）`
- `依次拍摄您的车（标的车）、其他出险车辆（三者车）的车牌号、VIN码和车损部位`
- `拍摄时，为了估损准确，请尽量按引导使用自动拍照`

#### 设计意图

- 首页固定横屏一屏，不引入上下滚动
- 通过品牌 logo、标题层级和须知卡片提升信任感与可读性
- 入口简单，降低首次使用成本
- 环境切换入口不新增可见说明，不改变首页可见文案和布局
- 非生产环境右下角显示透明环境标识：`本地`、`sit` 或 `实盘`

### 2. 拍照页

拍照页是当前系统的核心 UI，固定分为三栏。

#### 左侧信息区

常驻展示：

- 当前车辆
- 非车损步骤下的拍摄步骤：
  - `1、车牌号`
  - `2、VIN码`
- 车损步骤下的计数：
  - `车损照片 x/5 张`
- `查看已拍`

车损步骤下的附加规则：

- 当 `damageCount === 0` 时显示首张提示：
  - `请对准车损处，稳定后自动拍照`
- 当 `damageCount > 0` 时显示 `完成拍摄`

这一区域不再显示：

- `当前状态`
- `可继续补充其他损伤照片`

#### 中间相机区

相机区承担三类信息：

- 取景辅助框
- 顶部固定引导文案 `guideTip`
- 底部 AI 状态文案 `aiStatusText`

当前约束：

- 顶部只放步骤引导
- 底部只放动态 AI 状态
- 不在框上方重复叠放大段状态文字

#### 右侧操作区

- 非确认态：圆形拍照按钮 + 按钮文案
- 确认态：预览图 + `确认使用 / 重新拍摄`
- 若拍后轻质检判断当前照片存在风险，确认态会在预览图下方追加一条轻提示：
  - `照片可能偏模糊，建议重拍`
  - `照片可能偏暗，建议重拍`
  - `照片可能反光或过亮，建议重拍`
- 提示只做建议，不改变确认与重拍的原有事件，不弹窗，不强制拦截

按钮文案规则：

- AI 可用时显示 `手动拍照`
- AI 不可用时显示 `点击拍照`

### 3. 车牌步骤 UI

#### 辅助框

- 横向长方形
- 位于取景区中下部
- 通过 `normal / detected / stable / locked` 样式表达状态变化

#### 顶部提示

- `将车牌号放入框内`

#### 底部 AI 状态

- `正在识别车牌…`
- `已识别到目标`
- `请保持稳定`
- `已稳定，即将拍摄`
- `请靠近一点`
- `请稍微后退`
- `请调整目标位置`

#### 距离箭头

这是最近一轮真机调试中重点收敛过的交互。

当前实现：

- 箭头贴近车牌框上沿
- 框上方不再额外放文字
- 使用 6 组较窄的静态箭头
- 不是顺序流动，不做位移，不做缩放
- 用两整组静态帧切换颜色：
  - A 帧：`1/3/5 蓝，2/4/6 白`
  - B 帧：`1/3/5 白，2/4/6 蓝`

设计目的：

- 给出“方向”信号
- 不让箭头比车牌框更显眼
- 减少 `cover-view` 层动效导致的真机不稳定

### 4. VIN 步骤 UI

#### 辅助框

- 细长横条
- 位于取景区中下部

#### 顶部提示

- `请对准前挡风玻璃左下角VIN码，拍清完整字符`

#### 交互特点

- 当前主要依赖手动拍照
- 不叠加复杂 AI 引导

### 5. 车损步骤 UI

#### 辅助框

- 固定小方框
- 中心十字
- 当前视觉重点是“局部对准”，不是大范围取景

#### 顶部提示

- `请对准车损处`

#### 底部 AI 状态

- `正在识别车损…`
- `请对准车损处`
- `已识别到车损`
- `请靠近一点`
- `请稍微远离`
- `请保持稳定`
- `已稳定，即将拍摄`

#### 面积引导箭头

- 仅在已识别到车损、但面积比例不适合继续稳定判定时显示
- 面积过小：显示向前箭头，底部状态为 `请靠近一点`
- 面积过大：显示向后箭头，底部状态为 `请稍微远离`
- 位置贴近车损框上沿，不遮挡中心十字
- 视觉上复用车牌同款 6 组较窄静态箭头
- 蓝白颜色通过两整组静态帧切换，不使用流动位移动画

#### 状态表达

- `normal`：未识别到稳定目标
- `active`：已识别到车损或正在保持稳定
- `locked`：满足自动拍照条件

#### 开发态调试信息

仅非 `release` 环境显示：

- `phase`
- `area`：当前车损框整图面积占比 / 当前有效范围
- `center`：车损中心偏移
- `stable`：稳定度
- `hold`：HOLD 阶段连续稳定帧数

正式用户态不默认暴露这组调试文本。

### 6. 预览页

#### 主体结构

- 滚动区：车辆照片分组，每辆车照片列表末尾展示行驶证资料
- 固定底栏：行驶证轻提示、返回补拍/添加三者车入口、完成采集按钮

#### 单车分组结构

- 标题：车辆类型
- 车牌卡片
- VIN 卡片
- 多张车损卡片
- 行驶证资料卡片：
  - 未完成时显示 `上传行驶证` 虚线入口格
  - 已完成时展示真实图片缩略图与 `行驶证正页 / 行驶证副页 / 电子行驶证` 标签
- 补拍入口：
  - 车牌/VIN 缺失时显示 `+`
  - 车损未满 5 张时显示 `拍摄车损` 或 `添加车损`

#### 照片卡片

- 缩略图
- 底部标签：`车牌 / VIN码 / 车损x`
- 若来源是 AI 自动拍照，右上角显示 `自动`

#### 行驶证资料面板

- 点击 `上传行驶证` 后在当前预览页打开轻量面板，不跳转页面
- 默认实体模式：
  - 标题：`行驶证资料`
  - 上传位：`行驶证正页`、`行驶证副页`
  - 切换入口：`改传电子行驶证`
- 电子模式：
  - 标题：`电子行驶证`
  - 上传位：`电子行驶证`
  - 切换入口：`改传实体行驶证`
- 已上传上传位展示真实图片缩略图，不使用占位图
- 点击已上传位提供 `查看 / 重新上传 / 删除`
- 点击未上传位弹出 `拍照 / 从手机相册选择 / 取消`
- 若总照片已达到 50 张，继续拍照、补拍或上传时不进入新增流程，只显示轻提示 `最多50张，请先删除`

#### 底部栏

- 左侧：`行驶证资料未完成上传，可能影响后续智能定损和理赔处理。`
- 右侧：
  - `添加三者车`
  - `完成采集`

#### 提交确认弹窗

- 若仍可添加三者车，先显示：
  - 文案：`确认所有车辆损伤均已拍摄，无需增加其他三者车？`
  - 左按钮：`否，添加其他三者车`
  - 右按钮：`是，继续提交`
- 点击空白位置只关闭弹窗，停留预览页，不触发添加三者车流程
- 若存在任一车辆行驶证未完成，再显示：
  - 文案：`仍有车辆未上传行驶证，会影响定损金额准确性，建议上传。如确实无法提供，请后续联系案件处理人员补充。是否确认提交？`
  - 左按钮：`返回补充`
  - 右按钮：`确认提交`

#### 全屏预览

- 支持左右切换
- 顶部可关闭
- 底部支持 `重拍 / 删除`
- 显示拍摄方式标签：
  - `AI自动拍摄`
  - `手动拍摄`

### 7. 完成页

- 顶部成功图标 `✓`
- 主标题：`拍摄完成`
- 中部统计卡片：
  - 车辆数
  - 车损照片
  - 单证照片
- 提示：`所有照片已保存完成`
- 底部按钮：
  - `完成退出`
  - `返回修改`

### 8. 备用单证页

代码中仍保留独立 `document` 页面：

- 顶部标题 `单证资料上传`
- 中部照片网格
- 底部 `确认提交`
- 上传入口同样遵守 50 张总照片容量上限，达到上限时显示 `最多50张，请先删除`

但当前主流程默认在预览页底部完成单证处理，不主动跳入该页。

## 四、当前交互原则

### 1. 拍照优先级

- AI 自动拍照优先
- 手动拍照始终可用
- 确认/重拍是强制闭环

### 2. 状态文案分层

- 顶部 `guideTip`：步骤级提示
- 底部 `aiStatusText`：当前识别状态
- 左侧信息区：计数与流程入口

### 3. 覆盖层动效约束

- 不使用复杂流动动画
- 不在相机覆盖层做高频多元素渐变和位移
- 距离箭头改成整帧切换，优先稳定

### 4. 车损拍摄的 UI 取舍

- 不在左侧重复显示“当前状态”
- 不把首张提示和底部 AI 状态写成同一句反复出现
- 用小方框和十字强调“对准局部损伤”
- 面积引导只在必要时显示，并复用轻量静态箭头，不让提示层盖过目标框

### 5. 轻质检提示原则

- 轻质检提示只作为辅助建议，不替代用户判断
- 提示优先贴近当前操作节点显示：
  - 拍后确认阶段提示单张照片风险
- 提示文案必须克制，避免出现“质量不合格”“禁止提交”等强拦截表达
- 当没有风险时，不额外打扰用户

### 6. 自动化测试可见性

- v1.3.3 仅将 VIN 顶部提示、确认态按钮文案改为数据绑定，便于页面自动化断言。
- 该调整不新增视觉元素、不改变样式、不改变确认/重拍事件和主流程。

## v1.3.4 权限与反馈交互补充

### 首页开始采集

- `开始采集` 按钮视觉样式和首页布局不变。
- 点击后进入权限检查与跳转流程；流程未结束前，重复点击只忽略后续触发，不显示新的页面状态。
- 相机权限拒绝时停留在首页，不进入拍摄页。
- 相册权限拒绝时仍进入拍摄页；不新增阻断弹窗，不新增 UI 样式。
- 开始采集流程异常时使用轻提示：`开始采集失败，请重试`。

### 拍照确认态

- `确认使用 / 重新拍摄` 的按钮位置、样式和文案不变。
- 点击 `确认使用` 后，仍按原确认流程关闭确认态、写入缓存并推进下一步。
- 确认照片保存到系统相册成功时，业务 UI 不显示“照片已保存”“保存成功”“保存至手机相册”等成功提示。
- 保存失败时只显示轻提示：`照片未保存到相册，不影响拍摄`。
- 相册权限拒绝导致的保存跳过不逐张打扰用户。
- 点击 `重新拍摄` 时直接回到当前拍摄步骤，不触发相册保存。
- 安卓或微信系统可能显示原生保存成功提示；该提示不属于小程序 UI 反馈，不通过额外 `hideToast` 等方式绕过。

## v1.3.5 预览页行驶证交互补充

- 行驶证资料不再作为独立大模块出现，而是跟随每辆车照片列表末尾展示，降低横屏页面纵向占用。
- 未完成状态使用和照片缩略图一致的紧凑入口格，浅绿色底、虚线边框、绿色加号。
- 已完成状态使用真实图片缩略图，视觉上与车损照片保持一致。
