# 客户端错误日志上报接口设计

> 状态：设计中，尚未开发
> 最后更新：2026-05-18

## 1. 背景

`selfCam` 当前已在端上通过 `runtime-logger` 记录运行日志，并将部分 AI 排障事件同步到微信小程序实时日志。后续与在线平台后台联调时，需要一条独立接口把关键报错落到后台 Oracle 表，便于按报案号排查真机问题。

第一阶段目标是“先落库排障”，不是建设完整日志平台。

## 2. 设计结论

- 新增独立客户端错误日志上报接口，不与后续照片/案件资料业务提交接口合并。
- 只上传明确报错事件，不上传正常状态、页面行为、AI 几何诊断快照或普通调试日志。
- 后端只做校验、脱敏、幂等去重和落库。
- 前端统一在 `runtime-logger` 内部过滤、入队和上传，不在每个业务报错点直接调用后台接口。
- 小程序启动参数中的报案号字段名为 `reportNo`。
- 当前阶段不新增缺少 `reportNo` 的入口阻断；缺少 `reportNo` 时不上报后台，只保留本地日志。

## 3. 上报范围

第一版只上报以下失败事件：

| scope | event | 说明 |
| --- | --- | --- |
| `ai_model` | `download_failed` | 模型下载失败 |
| `ai_model` | `download_status_failed` | 模型下载状态码异常 |
| `ai_model` | `cache_copy_failed` | 模型缓存写入失败 |
| `ai_model` | `model_file_invalid` | 模型文件无效 |
| `ai_model` | `session_create_failed` | 推理 session 创建失败 |
| `ai_model` | `session_load_failed` | 推理 session 加载失败 |
| `ai` | `ai_unavailable` | AI 能力不可用 |
| `ai` | `detector_init_failed` | 检测器初始化失败 |
| `ai` | `detect_loop_error` | AI 检测循环异常 |
| `capture` | `auto_capture_failed` | 自动拍照异常 |
| `camera` | `camera_error` | 相机组件异常 |
| `api` | `request_failed` | 后续业务接口请求失败 |

第一版不上传：

- 页面加载、展示、卸载等生命周期日志
- 正常拍照、确认、跳转、保存流程日志
- `realtime_probe`
- `model_config_probe`
- `camera_layout_snapshot`
- `preview_layout_snapshot`
- `ai_geometry_snapshot`
- `auto_capture_gate_sample`
- `auto_capture_ready`

## 4. 接口定义

接口路径先按设计占位，最终以在线平台后端规范为准。

```http
POST /api/selfcam/v1/error-logs/batch
Content-Type: application/json
```

### 4.1 请求体

```json
{
  "appCode": "selfCam",
  "appVersion": "1.4.2",
  "clientType": "wechat_miniprogram",
  "appEnv": "sit",
  "wxEnvVersion": "trial",
  "reportNo": "RPT202605180001",
  "sessionId": "171xxxx-ab12cd",
  "feedbackId": "selfCam_171xxxx-ab12cd",
  "sentAt": "2026-05-18T10:20:30.000Z",
  "device": {
    "brand": "HUAWEI",
    "model": "nova13",
    "system": "OpenHarmony 4.x",
    "platform": "ohos",
    "SDKVersion": "3.x",
    "wechatVersion": "8.x"
  },
  "logs": [
    {
      "clientLogId": "171xxxx-a1b2c3",
      "level": "error",
      "scope": "ai_model",
      "event": "session_create_failed",
      "page": "camera",
      "step": "damage",
      "occurredAt": "2026-05-18T10:20:28.000Z",
      "message": "create session failed",
      "errMsg": "",
      "stage": "inference_session_create",
      "statusCode": "",
      "payload": {}
    }
  ]
}
```

### 4.2 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `appCode` | 是 | 固定为 `selfCam` |
| `appVersion` | 否 | 小程序当前版本 |
| `clientType` | 是 | 固定为 `wechat_miniprogram` |
| `appEnv` | 是 | 业务环境：`dev/sit/pilot/prod` |
| `wxEnvVersion` | 是 | 微信运行版本：`develop/trial/release` |
| `reportNo` | 是 | 报案号，来自小程序启动参数 |
| `sessionId` | 是 | 本次采集/排障会话 ID |
| `feedbackId` | 否 | 反馈过滤号，格式为 `selfCam_${sessionId}` |
| `sentAt` | 是 | 前端发送时间 |
| `device` | 否 | 设备与微信基础库信息 |
| `logs` | 是 | 错误日志数组，单批建议最多 20 条 |
| `logs[].clientLogId` | 是 | 前端日志 ID，用于幂等去重 |
| `logs[].level` | 是 | 第一版主要为 `error` |
| `logs[].scope` | 是 | 错误归属模块 |
| `logs[].event` | 是 | 错误事件名 |
| `logs[].page` | 否 | 发生页面 |
| `logs[].step` | 否 | 拍摄步骤 |
| `logs[].occurredAt` | 是 | 客户端发生时间 |
| `logs[].message` | 否 | 错误摘要 |
| `logs[].errMsg` | 否 | 微信 API 或运行时原始错误摘要 |
| `logs[].stage` | 否 | 失败阶段 |
| `logs[].statusCode` | 否 | HTTP 或下载状态码 |
| `logs[].payload` | 否 | 结构化上下文，必须裁剪和脱敏 |

### 4.3 响应体

```json
{
  "code": "SUCCESS",
  "message": "ok",
  "data": {
    "requestId": "srv-20260518-000001",
    "accepted": 1,
    "duplicated": 0,
    "rejected": 0
  }
}
```

### 4.4 接口规则

- `reportNo` 对接口必填；后端缺失时返回失败，不落库。
- `logs` 不能为空，单批最多建议 20 条。
- 后端按 `appCode + sessionId + clientLogId` 幂等去重。
- 重复日志计入 `duplicated`，不重复落库。
- 结构化字段无法解析时，允许将原始安全摘要落入 `payload_json`，但不能阻断整批可用日志落库。
- 接口不可用时，前端静默失败，不弹窗、不阻断拍照流程。

## 5. 前端实现方案

后续开发时，页面和业务模块仍只调用现有日志入口：

```js
runtimeLogger.error(scope, event, payload)
runtimeLogger.forceError(scope, event, payload)
```

不在各个报错点直接调用后台接口。

计划修改点：

1. `app.js` 从启动参数读取 `reportNo`，保存到全局上下文和本地缓存。
2. `env-config.js` 增加在线平台错误日志接口配置，例如 `errorLogUploadEnabled`、`errorLogUploadUrl`。
3. `runtime-logger.js` 增加错误上传白名单，只允许本设计列出的失败事件进入后台上传队列。
4. `runtime-logger.js` 内部新增错误上传队列、延迟批量发送和手动 flush 能力。
5. 有 `reportNo` 且接口开关开启时才上传；没有 `reportNo` 时只写本地日志。
6. 上传前统一补齐 `appCode`、`appVersion`、`clientType`、`appEnv`、`wxEnvVersion`、`sessionId`、`feedbackId`、`device`。
7. 上传前统一裁剪 `payload`，过滤敏感字段和过大内容。

批量策略：

- 接口按批量设计。
- 前端第一版可单条或小批量发送。
- 最多缓存 20 条待上传错误。
- 触发错误后延迟 1-2 秒合并发送。
- 页面退出或 session 结束时可尝试 flush。
- 失败静默处理，不做影响体验的强重试。

## 6. Oracle 表设计

表名建议：

```sql
SELF_CAM_ERROR_LOG
```

DDL 建议：

```sql
CREATE TABLE SELF_CAM_ERROR_LOG (
  ID NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

  APP_CODE VARCHAR2(32) NOT NULL,
  APP_VERSION VARCHAR2(32),
  CLIENT_TYPE VARCHAR2(32),

  APP_ENV VARCHAR2(16),
  WX_ENV_VERSION VARCHAR2(16),

  REPORT_NO VARCHAR2(64) NOT NULL,
  SESSION_ID VARCHAR2(128),
  FEEDBACK_ID VARCHAR2(160),
  CLIENT_LOG_ID VARCHAR2(128),

  LOG_LEVEL VARCHAR2(16),
  SCOPE VARCHAR2(64),
  EVENT VARCHAR2(128),
  PAGE_NAME VARCHAR2(64),
  STEP_NAME VARCHAR2(64),

  MESSAGE VARCHAR2(1000),
  ERR_MSG VARCHAR2(1000),
  ERROR_CODE VARCHAR2(128),
  STAGE VARCHAR2(128),
  STATUS_CODE VARCHAR2(32),

  DEVICE_JSON CLOB,
  PAYLOAD_JSON CLOB,

  OCCURRED_AT TIMESTAMP(3),
  SENT_AT TIMESTAMP(3),
  RECEIVED_AT TIMESTAMP(3) DEFAULT SYSTIMESTAMP NOT NULL
);
```

索引建议：

```sql
CREATE UNIQUE INDEX UK_SELF_CAM_ERR_CLIENT
ON SELF_CAM_ERROR_LOG (APP_CODE, SESSION_ID, CLIENT_LOG_ID);

CREATE INDEX IDX_SELF_CAM_ERR_REPORT_NO
ON SELF_CAM_ERROR_LOG (REPORT_NO);

CREATE INDEX IDX_SELF_CAM_ERR_FEEDBACK_ID
ON SELF_CAM_ERROR_LOG (FEEDBACK_ID);

CREATE INDEX IDX_SELF_CAM_ERR_EVENT_TIME
ON SELF_CAM_ERROR_LOG (SCOPE, EVENT, OCCURRED_AT);

CREATE INDEX IDX_SELF_CAM_ERR_ENV_TIME
ON SELF_CAM_ERROR_LOG (APP_ENV, OCCURRED_AT);
```

如果目标 Oracle 版本不支持 `IDENTITY`，改用 `SEQUENCE + TRIGGER` 生成主键。

## 7. 敏感信息边界

前端不得上传：

- 图片、base64、相机原始帧
- token、cookie、session key、密钥
- 身份证号、驾驶证号、完整 VIN、完整车牌号
- 用户手机号、精确定位
- 完整本地文件内容

后端也需要做二次兜底：

- 对敏感 key 拒收或脱敏
- 对 `payload_json` 做长度限制
- 对异常大请求直接拒绝

## 8. 联调验收标准

- 启动参数带 `reportNo` 时，错误日志请求体包含该报案号。
- 正常拍照流程不产生后台错误日志。
- 触发模型下载失败、session 创建失败、相机错误时，后台能按 `REPORT_NO` 查到。
- 错误接口不可用时，小程序仍能继续拍照。
- 重复上报同一 `clientLogId` 不重复落库。
- 后台不落图片、base64、token、cookie、完整 VIN、完整车牌号等敏感内容。

## 9. 暂不实现

- 缺少 `reportNo` 时阻断进入小程序。
- 完整业务提交接口。
- 照片或单证文件上传接口。
- 后台日志处理流转、告警和自动清理。
- 正常状态、诊断快照和用户行为日志落库。
