# 弹窗交互清单

## 文档目标

本文档用于统一维护 selfCam 小程序中的弹窗、弹层、遮罩和系统原生菜单，帮助后续判断新增或调整提示时是否会造成重复打断、连续弹窗或文案口径不一致。

本文档不维护 `toast`、`loading` 这类一闪而过的轻提示。轻提示不应承载关键业务决策；若后续发现重要信息只能通过轻提示传达，应优先改为页面内状态、入口置灰说明或正式业务弹窗。

## 维护原则

- 能在页面内展示的提示，不新增强弹窗。
- 权限类提示优先使用微信原生能力。
- 业务风险类可以强弹，但同一用户动作后原则上不连续出现多个业务确认弹窗。
- 流程交接弹层只说明当前完成状态和下一步，不写过长解释文案。
- 状态遮罩只用于上传、提交、失败重试等用户不应随意离开的阶段。
- 新增、删除或调整主流程弹窗时，必须同步更新本文档。

## 弹窗分类

| 分类 | 定义 | 当前示例 |
|---|---|---|
| 系统弹窗 | 微信原生权限确认或系统菜单 | 摄像头权限、相册权限、证件来源选择 |
| 业务确认弹窗 | 用户必须做出选择后才能继续 | 缺失现场照确认、证件缺失风险确认、保存相册确认 |
| 拍摄指引弹层 | 拍照前说明拍摄要求的自定义弹层 | 整车 45 度指引、车损远中近指引 |
| 流程交接弹层 | 告知当前环节完成并引导进入下一步 | 模块一到车损、车损到证件、证件到最终预览 |
| 状态遮罩 | 上传、完成提交、失败重试等流程状态 | 上传中、上传失败、完成提交失败、采集提交完成 |

| 拍照页首次进入 | 车损远中近拍摄指引 | 拍摄指引弹层 | 首次进入首车车损拍摄，且未看过指引 | `拍摄指引：车损处远、中、近拍摄`；图示文字：`远 / 中 / 近` | `知道了，开始拍摄` | 是 | 保留 |

| 模块一预览 | 补充现场信息提示 | 业务确认弹窗 | 模块一主照片完成后首次进入预览 | `是否补充其他现场环境或道路相关损失？`；`如护栏、灯杆、路牌、路面痕迹等` | `没有了 / 去拍摄` | 是 | 待评估是否改为页面内提示 |
| 模块一进车损前 | 缺失现场照确认 | 业务确认弹窗 | 用户未拍整车现场照但要进入车损拍摄 | `现场照片未采集，建议补拍，便于记录事故现场和车辆整体状态。` | `返回补拍 / 仍然进入车损拍摄` | 是 | 本次修改 |
| 模块一到车损 | 环节完成交接弹层 | 流程交接弹层 | 模块一完成后准备进入车损拍摄 | `现场环境及车辆信息已保存`；进度清单：`已完成：现场环境及车辆信息`、`下一步：车损照片拍摄`、`未完成：证件信息` | `返回预览 / 进入车损拍摄` | 是 | 本次修改 |
| 车损到证件 | 环节完成交接弹层 | 流程交接弹层 | 车损照片完成后准备进入证件信息 | `车损照片已保存`；进度清单：`已完成：现场环境及车辆信息`、`已完成：车损照片拍摄`、`下一步：证件信息` | `返回预览 / 进入证件信息` | 是 | 本次修改 |
| 证件到最终预览 | 环节完成交接弹层 | 流程交接弹层 | 证件信息环节后准备进入最终总预览 | `证件信息已保存`；证件齐全时显示 `已完成：证件信息`，证件不全时显示 `待补充：证件信息`；同时显示 `已完成：现场环境及车辆信息`、`已完成：车损照片拍摄` | `返回预览 / 进入最终总预览` | 是 | 本次修改 |
| 最终提交前 | 三者车确认 | 业务确认弹窗 | 最终提交时仍允许添加三者车；仅普通/非 ticket 流程出现；后端 ticket 辅助拍照流程不展示 | `确认所有车辆损伤均已拍摄，无需增加其他三者车？` | `否，添加其他三者车 / 是，继续提交` | 是 | 待评估是否与提交前确认合并 |
| 最终提交前 | 证件缺失风险确认 | 业务确认弹窗 | 最终提交时证件信息不完整 | `证件信息不全，建议补充驾驶证和行驶证。如确实无法提供，可后续通过其他方式提供。是否确认提交？` | `返回补充 / 确认提交` | 是 | 本次修改 |
| 最终提交前 | 保存全部图片至相册 | 业务确认弹窗 | 提交前存在未保存到手机相册的全部图片 | `是否保存全部图片至手机相册？建议保存，便于后续案件处理。` | `暂不保存 / 保存至手机` | 是 | 保留 |
| 最终提交前 | 保存新增图片至相册 | 业务确认弹窗 | 提交前仅存在未保存到手机相册的新增图片 | `是否保存新增图片至手机相册？建议保存，便于后续案件处理。` | `暂不保存 / 保存至手机` | 是 | 保留 |
| 提交后 | 上传中遮罩 | 状态遮罩 | 提交后正在上传照片 | `正在上传照片`；`请保持小程序打开，上传完成后继续下一步。`；`已上传 X/Y`；`当前：{照片项}` | 无 | 是 | 保留 |

| 提交后 | 正在完成提交遮罩 | 状态遮罩 | 已上传照片，正在调用完成提交 | `正在完成提交`；`照片已上传，请保持小程序打开。`；`正在确认采集完成` | 无 | 是 | 保留 |

## 系统弹窗与原生菜单

| 环节 | 名称 | 原生能力 | 触发条件 | 展示文字或选项 | 维护说明 |
|---|---|---|---|---|---|
| 首页开始采集 | 摄像头权限弹窗 | `wx.showModal` | 开始采集但相机未授权或已拒绝 | `摄像头权限`；`需要开启摄像头权限后才能拍摄车辆照片`；`去设置 / 取消` | 必要系统权限弹窗 |
| 拍照页报错 | 摄像头权限弹窗 | `wx.showModal` | `<camera>` 组件报错 | `相机权限`；`请授权使用摄像头` | 建议后续与首页权限文案统一 |
| 最终提交前 | 相册权限弹窗 | `wx.showModal` | 用户选择保存至手机，但相册保存权限未授权或已拒绝 | `相册权限`；`需要开启相册保存权限后，才能将采集照片保存到手机相册`；`去设置 / 取消` | 必要系统权限弹窗 |
| 证件上传 | 电子/实物证件选择 | 修改前为 `wx.showActionSheet`；本次改为自定义面板分段切换 | 点击上传证件入口或实物证件单侧缺失补拍入口 | 修改前选项为 `电子{证件名}`、`实物{证件名}`；本次改为 `电子证件 / 实物证件` | 修改前代码现状是先原生 `wx.showActionSheet`，再进入自定义证件面板；本次修改后不再作为系统原生菜单维护。点击缺失正页/副页入口默认进入实物证件面板；只有电子证件时不展示实物入口，实物正副页齐全时不展示电子入口；电子 + 实物单侧时仍展示缺失实物侧入口 |
| 证件上传 | 证件图片来源选择 | `wx.showActionSheet` | 点击未上传的证件槽位 | `拍照`、`从手机相册选择` | 保留 |
| 证件上传 | 已上传证件操作 | `wx.showActionSheet` | 点击已上传的证件槽位 | `查看`、`重新上传`、`删除` | 保留，删除仍需二次确认 |

## 本次优化决策

| 序号 | 决策 | 说明 |
|---|---|---|
| 1 | 电子/实物证件选择改回自定义证件面板内切换 | 修改前代码现状是先弹微信原生 `wx.showActionSheet`，再进入自定义证件面板；本次取消该原生菜单，点击证件入口后直接打开自定义证件面板，在面板顶部使用 `电子证件 / 实物证件` 分段切换。 |
| 2 | 删除模块三进入最终预览前的证件缺失轻提示 | 删除一闪而过的黑色 `toast`，避免和后续交接弹层、最终提交风险确认重复。 |
| 3 | 缺失现场照确认精简文案 | 删除 `你也可以继续进入车损照片拍摄。`，是否继续由按钮表达。 |
| 4 | 三个模块交接弹层删除说明文案 | 不再展示 `本环节照片将后台上传...` 或 `证件缺失不影响继续...` 这类说明，改为进度清单。 |
| 5 | 模块交接弹层改为完成状态清单 | 展示 `已完成 / 下一步 / 待补充`，帮助用户判断当前进度。 |
| 6 | 证件缺失风险确认文案改短 | 改为 `证件信息不全，建议补充驾驶证和行驶证。如确实无法提供，可后续通过其他方式提供。是否确认提交？` |
| 7 | 证件完成状态按实际情况展示 | 证件齐全时显示 `已完成：证件信息`；证件不全时显示 `待补充：证件信息`，避免和提交前风险提示冲突。 |
| 8 | 模块二车损低数量完成改为软确认 | 少于 3 张点击 `完成本车拍摄` 时先提示照片较少；用户仍可确认完成，不做硬拦截。 |
| 9 | 按 `E/F/B` 矩阵保留必要补拍入口 | 电子证件 1 张或实物正页 + 副页满足其一即可提交完成；预览页始终展示已采集照片，只有电子证件时不补实物，实物正副页齐全时不补电子；只要实物链路已开始但正副页未齐全，包括电子 + 实物单侧过渡态，都展示另一侧 `+` 入口，点击后进入实物证件面板。 |

## 后续待评估项

- 是否合并最终提交前的三者车确认、证件缺失风险确认、保存相册确认，减少连续弹窗。
- 是否把“补充现场信息提示”从强弹改为模块一预览页内提示卡。
- 是否统一 `confirm-modal` 与流程交接/上传遮罩的视觉规范。
- 是否清理未使用的 `photo-menu` 组件。
- 是否清理预览页中未渲染的备用 `showActionSheet` 状态和相关方法。
