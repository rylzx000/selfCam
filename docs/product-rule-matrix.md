# 产品规则矩阵

## 文档目的

本文档是 selfCam 当前四段采集流程的产品规则单一事实源。后续新增、修改或审查测试时，优先以本文档为准；若 Jest、页面可操作性测试、automator/e2e、真机 smoke 或其他测试说明与本文档冲突，应先标记为规则漂移，再按本文档纠偏。

术语说明：本文保留 `Jest`、`automator`、`e2e`、`actionSheet`、`documentSelections`、`ticket`、`uploadItems`、`E/F/B` 等英文或代码字段，是因为它们是测试框架、微信原生能力、代码字段、接口字段或机器可读缩写，翻译会降低可追溯性。

## 一、总原则

- 所有测试规则以本产品规则矩阵为准，流程路由矩阵、测试运行指引和历史 change 只能作为覆盖索引或背景材料。
- `Jest` 负责规则、状态、缓存、路由和工具函数的确定性验证。
- 页面可操作性测试负责证明“页面上是否有入口、入口是否能点、点后去哪”，不得只依赖页面方法调用。
- `automator/e2e` 负责真实页面主链路、高风险恢复链路、真实页面栈和开发者工具环境差异。
- 手工/真机负责相机硬件、系统权限、横屏适配、真实触摸区域、真实文件写入、压缩耗时和微信环境差异。
- 旧测试若验证旧规则，即使当前通过，也不得视为产品正确性证明。
- 待确认规则不得写成已实现规则；测试只能按已确认规则固化。

## 三、模块二：车损照片拍摄

模块二当前规则：每车最多 10 张车损照片。不再有 5 张上限；任何“5 张满图”或“第 6 张拒绝”的测试口径都是旧规则。测试应以 10 张作为满图状态，并验证第 11 张被拒绝或不再新增；5 张可以作为普通中间状态测试，但不得作为上限或满图状态。

| 状态/场景 | 页面展示 | 用户操作 | 预期跳转或结果 | 测试层级建议 |
|---|---|---|---|---|
| 第一辆车进入车损 | 拍照页进入第一辆车 `damage` | 从模块一交接弹层进入 | 不拍车牌/VIN，直接采集车损 | Jest、e2e |

| 多车下一辆 | 当前车完成且还有下一辆 | 点击下一辆车 | 留在拍照页并切到下一辆车 `damage` | Jest、e2e |

## 四、模块三：证件信息

定义：`E` 表示电子证件，`F` 表示实物正页，`B` 表示实物副页。驾驶证和行驶证均使用同一矩阵。

正确规则：

- 每辆车采集驾驶证和行驶证。
- 每类证件支持电子证件 1 张，或实物正页 + 副页 2 张。
- 电子证件 1 张可完成。
- 实物正页 + 副页可完成。
- 完成状态为“电子存在 OR 实物正副页齐全”。
- 如果用户已经开始实物链路，只拍了 `F` 或 `B`，应展示另一侧实物补传入口。
- 即使 `E` 已存在，如果又拍了 `F` 或 `B`，也允许补齐另一侧实物，所以 `E+F` 展示 `B+`，`E+B` 展示 `F+`。
- 只有 `E` 时，不展示 `F/B +`。
- `F+B` 时，不展示 `E +`。
- `E+F+B` 展示三张，不展示 `+`。
- 打开面板、切换 tab、关闭面板，不改变 `documentSelections`。
- 只有成功保存照片后，才根据保存 side 更新 `documentSelections`。
- 点击证件入口直接打开自定义证件面板；只有点击面板内未上传槽位才弹“拍照/相册”原生 `actionSheet`。
- 模块三进入最终预览前不再 toast；通过交接弹层展示“待补充：证件信息”，最终提交前才提示证件风险。

| 状态 | 页面展示什么 | 是否完成 | 是否展示 `+` | 点击 `+` 后打开什么 | 是否会改变 `documentSelections` | 测试层级建议 |
|---|---|---|---|---|---|---|
| 空状态 | 基础入口“驾驶证”或“行驶证” | 否 | 是 | 自定义证件面板，默认电子证件；用户可切换实物证件 | 打开、切换、关闭不改变；保存后改变 | Jest、页面可操作性、e2e |
| `E` | 电子证件照片 | 是 | 否 | 无 `+` | 无操作不改变 | Jest、页面可操作性 |
| `F` | 实物正页照片 + 实物副页 `+` | 否 | 是，展示 `B+` | 自定义证件面板，默认实物证件 | 打开不改变；保存副页后改为 physical | Jest、页面可操作性 |
| `B` | 实物正页 `+` + 实物副页照片 | 否 | 是，展示 `F+` | 自定义证件面板，默认实物证件 | 打开不改变；保存正页后改为 physical | Jest、页面可操作性 |
| `E+F` | 电子证件照片 + 实物正页照片 + 实物副页 `+` | 是 | 是，展示 `B+` | 自定义证件面板，默认实物证件 | 打开不改变；保存副页后改为 physical | Jest、页面可操作性、e2e |
| `E+B` | 电子证件照片 + 实物正页 `+` + 实物副页照片 | 是 | 是，展示 `F+` | 自定义证件面板，默认实物证件 | 打开不改变；保存正页后改为 physical | Jest、页面可操作性、e2e |
| `F+B` | 实物正页照片 + 实物副页照片 | 是 | 否 | 无 `+` | 无操作不改变 | Jest、页面可操作性 |
| `E+F+B` | 电子证件、实物正页、实物副页三张全部展示 | 是 | 否 | 无 `+` | 无操作不改变 | Jest、页面可操作性 |

## 七、异常与破坏性场景

| 分类 | 场景 | 预期处理 | 测试层级建议 |
|---|---|---|---|
| 权限拒绝 | 相机权限拒绝 | 不初始化采集、不跳空白相机页，提示授权路径 | Jest、真机 |
| 权限拒绝 | 相册保存权限拒绝 | 不阻断完成提交，记录保存失败结果 | Jest、真机 |
| 用户取消 | 取消拍照或取消相册选择 | 不新增照片、不改变完成态，保留当前页面 | Jest、页面可操作性 |
| 系统 API 失败 | `takePhoto` 失败 | 给出可恢复提示，不写入坏照片 | Jest、真机 |
| 系统 API 失败 | `chooseMedia` 失败 | 不新增照片、不改变 `documentSelections` | Jest、页面可操作性 |
| 系统 API 失败 | `compressImage` 失败 | 提示处理失败，不保存坏数据 | Jest、真机 |
| 上传失败 | 上传失败或网络断开 | 保留 `uploadSession`，失败项可重试，成功项不重传 | Jest、e2e |
| 缓存异常 | 缓存损坏、缺字段或旧 schema | 安全恢复或回首页，不白屏 | Jest、e2e |
| 快速重复点击 | 连续确认、重复完成、重复打开关闭弹层 | 不重复写入、不重复推进、不串车 | Jest、e2e |
| 多车组合 | 多车 + 满 10 张 + 删除 + 补拍 | 车辆归属、排序、统计保持一致 | Jest、e2e |
| 横屏适配 | 小屏、低端机、真实触摸区域 | 文案不溢出，按钮和图片真实可点 | 真机、视觉 smoke |
